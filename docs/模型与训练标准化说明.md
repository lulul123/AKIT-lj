# A-KIT 模型与训练标准化说明

## 1. 目的

本规范落实 `ai流程化.md` 中第二阶段“模型管理”的要求。它解决以下问题：

- 训练参数不再只散落在 Python 源码中；
- 不同模型使用相同的输入、输出和构建方式；
- 训练结果能够追溯到数据划分、配置、代码版本和归一化参数；
- 更换 CNN、LSTM、Transformer 等模型时，不重复实现 Kalman 传播和训练主流程。

当前版本号为 `akit-training-config-1`，模型接口版本为 `akit-model-1`。

## 2. 文件职责

### 2.1 标准化核心

| 文件 | 作用 | 是否在正式训练中使用 |
| --- | --- | --- |
| `configs/akit_set_transformer.json` | 一次实验的标准配置，记录数据划分、模型、优化器和 checkpoint 策略 | 是 |
| `schemas/training.schema.json` | 训练配置的机器可读结构约束 | 校验时使用 |
| `Code/akit_model_api.py` | 模型接口版本、模型注册表、统一构建函数和张量形状检查 | 是 |
| `Code/A-KIT_lj_agent.py` | 当前训练入口；加载数据、构建模型、运行间接监督 Kalman 链路、验证并保存权重 | 是 |
| `Code/akit_runtime.py` | 随机种子、设备、输出目录、环境记录和 checkpoint 公共函数 | 是 |
| `Code/akit_utils_agent.py` | 数据读取、时间对齐、Dataset 和可微 Kalman 计算 | 是 |
| `tools/validate_training_config.py` | 在训练前快速检查 JSON 配置的关键字段及一致性 | 建议每次配置修改后运行 |
| `Code/smoke_test.py` | 用合成小数据检查模型构建、前向、反向、Kalman 和 checkpoint | 建议代码修改后运行 |

### 2.2 数据与数值检查

| 文件 | 作用 | 不负责的内容 |
| --- | --- | --- |
| `tools/validate_dataset.py` | 检查 catalog、必需文件、列数、矩阵形状、有限数和基础时间顺序 | 不证明物理语义正确 |
| `tools/validate_ppred_replay.py` | 从 `PStart` 逐步回放 `Phi/dt/Qc` 并与 C++ `PPredCpp` 比较 | 不训练模型 |
| `Code/resample_500_to_100.py` | 将 500 Hz IMU/速度数据转换为每秒 100 点 | 不做训练划分 |
| `data/count_epochs.py` | 历史数据统计辅助脚本 | 当前不属于标准训练入口 |

### 2.3 历史文件

`Code/A-KIT_clean.py` 是早期独立训练实现，用于参考和对照。当前标准流程以
`Code/A-KIT_lj_agent.py` 为准；除非专门做历史复现，不应从 `A-KIT_clean.py`
启动新实验。

## 3. 训练配置

标准配置分为六部分：

- `experiment`：实验名称、随机种子、设备和输出目录；
- `data`：数据 catalog、训练/验证 split、序列长度和归一化策略；
- `model`：注册名、接口版本、输入输出语义和构造参数；
- `training`：epoch、batch、优化器、损失和梯度裁剪；
- `checkpoint`：最优权重与最终权重的保存策略；
- `schema_version`：配置格式版本，防止旧配置被静默误读。

数据目录不在训练配置中重复逐条填写。训练入口读取 `data/datasets.json`，按
`train_splits` 和 `validation_splits` 自动解析轨迹，保证数据 catalog 是唯一来源。

检查配置：

```bash
python tools/validate_training_config.py configs/akit_set_transformer.json
```

## 4. 模型接口

所有模型都必须遵守：

```python
raw_output = model(imu, p_start)
```

张量契约：

| 名称 | 形状 | 含义 |
| --- | --- | --- |
| `imu` | `(B, C, T)` | 已归一化的 IMU 与速度时间窗；当前 `C=9`、`T=100` |
| `p_start` | `(B, N, N)` | GNSS 区间起点的后验协方差；当前 `N=15` |
| `raw_output` | `(B, N)` | Qc 状态维缩放因子的原始 logits |

模型不应自行执行 `softplus`、Phi 回放、Kalman 更新或位置损失。这些属于训练任务
公共层。当前公共层执行：

```text
raw logits → softplus → Qc 缩放 → 逐步协方差传播
           → GNSS Kalman 更新 → 位置预测 → 位置 MSE
```

这样，相同模型输出语义可用于不同网络结构，也能避免每个模型复制一套科学计算代码。

## 5. 模型注册与复用

当前 Set Transformer 在训练模块中注册：

```python
register_model("set_transformer", Network)
```

训练入口使用以下方式构造，而不直接写死模型类：

```python
model = build_model(config["model"])
```

新增模型的最小步骤：

1. 新建 `torch.nn.Module`，实现 `forward(imu, p_start)`；
2. 保证输出为 `(B, state_dim)` 且不包含 NaN/Inf；
3. 使用唯一名称调用 `register_model()`；
4. 在训练 JSON 中修改 `model.name` 和 `model.parameters`；
5. 运行配置检查和 smoke test；
6. 先运行小规模实验，再进行正式训练。

目前注册发生在 `A-KIT_lj_agent.py` 中，因此新模型仍需由训练入口导入后注册。
后续模型数量增多时，应将各模型移动到独立的 `Code/models/` 包并集中发现注册。

## 6. 运行方式

配置化小实验：

```bash
python Code/A-KIT_lj_agent.py \
  --config configs/akit_set_transformer.json \
  --small --epochs 1
```

正式训练：

```bash
python Code/A-KIT_lj_agent.py \
  --config configs/akit_set_transformer.json
```

显式命令行参数会覆盖 JSON 中对应的 epoch、batch size 或 learning rate，便于诊断；
正式实验应尽量把最终参数写回 JSON，避免配置只存在于命令历史中。

## 7. 输出与可复现性

每次训练创建独立时间戳目录，并保存：

- 实际运行配置 `config.json`；
- Python、PyTorch、CUDA、Git commit 等 `environment.json`；
- 实际数据划分 `split_manifest.json`；
- 训练集 IMU 均值和标准差；
- 模型、优化器、调度器、epoch、指标和随机状态组成的 checkpoint。

checkpoint 保存的是 `state_dict` 和元数据，不依赖 pickle 整个模型对象。恢复模型时应先
按 checkpoint 中的配置调用 `build_model()`，再加载 `model_state_dict`。

## 8. 当前边界与后续工作

当前完成的是模型管理 v1，还存在以下边界：

- 训练循环仍集中在较大的 `A-KIT_lj_agent.py` 中；
- 目前只注册了 `set_transformer`；
- 配置检查工具执行核心检查，尚未依赖 `jsonschema` 做完整 Schema 校验；
- 推理接口、IPS 文件调用和超时回退属于第三阶段，尚未纳入本接口；
- 跨 GPS 周的特殊长 GNSS 区间目前由数据集过滤，不作为普通一秒训练样本。

建议下一步将训练循环拆成 Trainer，并把模型实现移动到独立 `models` 目录；在此之前，
当前接口已经足以固定模型输入输出语义，并支持第二个模型的对比接入。
