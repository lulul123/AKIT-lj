# A-KIT 数据总说明

## 1. 文档目的

本文是当前数据语义、时间戳对齐和 Kalman 应用的唯一总说明。训练代码和数据检查器应以本文为准。

当前技术路线是：网络每个 GNSS 区间输出 15 维连续时间过程噪声 `Qc` 缩放因子，Python 用区间内的单步 `Phi/dt` 逐步重放协方差，再使用同一 GNSS 时刻的 `H/R/Inno/GNSSMech` 完成更新并与参考 ECEF 位置计算损失。`PhiAcc/QAcc` 是已废弃的旧接口。

## 2. 统一时间轴

以 GNSS 更新时刻 `k=1001` 为例：

```text
1000 s GNSS更新后
    名义状态 x_1000+
    验后协方差 P_1000+
           |
           | IMU/Vel样本:       1000 <= t < 1001
           | Phi传播步:       1000 < t_end <= 1001
           | P_i = Phi_i P_(i-1) Phi_i^T + Q_i
           v
1001 s GNSS更新前
    GNSSMech(1001) = x_1001-
    P_pred(1001)    = P_1001-
           |
           | H(1001), R(1001), Inno(1001)
           v
1001 s GNSS更新后
    名义状态 x_1001+
    验后协方差 P_1001+
```

样本键 `k` 表示“目标 GNSS 更新时刻”。同一键下不同文件的矩阵可以对应不同的物理时刻；最典型的是 `PStart(k)` 的内容实际为上一次成功 GNSS 更新后的协方差。

## 3. 每个文件的数据契约

### 3.1 `imu.txt`

```text
Time Gyro_X Gyro_Y Gyro_Z Accel_X Accel_Y Accel_Z
```

- 每条 7 列：时间戳 + 3 轴角速度 + 3 轴比力。
- 样本 `k` 使用 `k-1 <= t < k` 的记录。
- 预期采样率为 100 Hz；当前网络输入固定为 100 步，因此 IMU 仍需要每个完整样本 100 条。
- IMU 用于网络推断 `Qc` 缩放；Python 不用它重做完整惯导机械编排。

### 3.2 `Vel.txt`

```text
Time Vx Vy Vz
```

- 是惯导机械编排速度，不是 GNSS 测速。
- 当前数据为 ECEF 速度，单位 `m/s`。
- 按 IMU 时间戳进行容差匹配，与 IMU 合成每步 9 维网络输入。
- 样本 `k` 使用 `k-1 <= t < k`。

### 3.3 `Phi.txt`

```text
WeekSecond DeltTime Phi
```

- 每条完整记录含 `1 + 1 + 15*15 = 227` 个数字：传播终点 `t`、`dt`和 `15x15 Phi`。
- 矩阵写出可能换行，不能用单个文本行的列数判断记录长度。
- `(t, dt, Phi)` 表示从 `t-dt` 传播到 `t`：

  \[
  \Phi=\exp(F\,dt)
  \]

- 样本 `k` 必须使用 `k-1 < t <= k`，与 IMU/Vel 的左闭右开规则不同。
- GNSS 整秒对齐可能拆分一个 IMU 步，因此一个区间的 Phi 数量不保证为 100。
- 应校验首尾边界、相邻步连续性、`dt > 0` 以及 `sum(dt)` 是否等于实际 GNSS 区间长度。
- `PStart(k)` 实际从上一次成功 GNSS 边界开始。当相邻成功边界间隔大于 1 s 时，正确 Phi 应覆盖整个多秒区间；当前网络只接收 1 s IMU，因此这类样本必须跳过，不能只使用最后一秒 Phi。

### 3.4 `Qc.txt`

- 一个 `15x15` 连续时间过程噪声强度矩阵，当前按轨迹作为常量读取。
- 网络输出 15 维正缩放因子，用于构造当前样本的预测 `Qc`。
- 每个 Phi 步的离散过程噪声使用 C++ 同款公式：

  \[
  Q_i=\frac{1}{2}(\Phi_iQ_c\Phi_i^T+Q_c)dt_i
  \]

### 3.5 `PStart.txt`

```text
WeekSecond PStart
```

- 每条为时间键 + `15x15` 协方差。
- Git 历史中的实际导出逻辑已确认：上一次成功 GNSS 更新后的第一次传播之前，以当时的验后 `StateP` 保存 `m_PStart`；当下一次 GNSS 位置更新成功时，以当前 GNSS 时间键写出。
- 因此对于相邻成功更新 `k-1 -> k`：

  \[
  PStart(k)=P_{k-1}^{+}
  \]

- `k` 是它服务的目标 GNSS 更新键；矩阵的物理时刻是上一成功更新后。
- 第一次成功 GNSS 更新只建立起始边界，不输出之前的不完整区间。

### 3.6 `GNSSMech.txt`

```text
WeekSecond Position(3) Velocity(3) AttitudeRad(3) AccelBias(3) GyrosBias(3)
```

- 时间戳后的 15 维顺序为位置、速度、姿态角、加速度计零偏、陀螺仪零偏。
- `GNSSMech(k)` 是机械编排已到达 `k`、但 `k` 时刻闭环反馈尚未执行的名义状态：

  \[
  GNSSMech(k)=x_k^{-}
  \]

- 它不是 `x_(k-1)+`，也不是 Kalman 误差状态 `StateX`。
- Python 直接使用它作为更新前名义状态，不再用 IMU 重做机械编排。
- 位置和速度为 ECEF；位置单位米，速度单位 `m/s`，姿态角单位弧度。

### 3.7 `H.txt`、`R.txt`、`Inno.txt`

- `H(k)` 为 `3x15` GNSS 位置观测矩阵。
- `R(k)` 为 `3x3` GNSS 位置观测噪声协方差。
- `Inno(k)` 为 `3x1` 位置创新。
- 三者均对应时刻 `k` 的同一次 GNSS 更新，必须与 `GNSSMech(k)` 和由 `PStart(k)` 传播得到的 `P_k-` 联用。
- ECEF 位置观测代码中：

  \[
  Inno=(INS\ predicted\ antenna\ position)-GNSS
  \]

- Kalman 内部估计误差状态 `delta_x = K Inno`，名义位置/速度使用减法反馈：

  \[
  x_k^{+}=GNSSMech(k)-\delta x_k
  \]

  上式对位置和速度分量直接成立；姿态应使用 C++ 的失准角旋转改正，不应简化成欧拉角逐元素加减。

### 3.8 参考位置

- 参考文件为每条轨迹目录中的 `.IMR.ref`/`.ref`/`.pos` 文件。
- 当前损失使用参考文件的 ECEF `X/Y/Z`，单位米。
- 标签必须与样本键 `k` 对齐，并且训练/验证/测试应按完整轨迹划分，不应随机拆分相邻秒。

## 4. 样本 `k` 的完整对应关系

| 数据 | 选取规则 | 物理含义 | 后续用途 |
|---|---|---|---|
| IMU | `k-1 <= t < k` | 区间内高频惯性观测 | 网络输入 |
| Vel | 与 IMU 时间戳匹配 | 区间内机械编排 ECEF 速度 | 网络输入 |
| Phi/dt | `k-1 < t_end <= k` | 从上一边界传播到 `k` | 逐步传播 P |
| Qc | 轨迹常量 + 网络缩放 | 连续时间过程噪声 | 每步构造 Q_i |
| PStart(k) | 精确键 `k` | 上一成功更新后 `P+` | 区间 P 传播起点 |
| GNSSMech(k) | 精确键 `k` | `k` 时刻更新前名义状态 | 名义状态起点 |
| H/R/Inno(k) | 精确键 `k` | `k` 时刻 GNSS 观测更新 | Kalman 更新 |
| reference(k) | 精确/有容差的键 `k` | `k` 时刻参考 ECEF 位置 | 监督损失 |

## 5. 正确的 Kalman 重放

对每个样本独立读取 `PStart(k)`，不在随机 batch 之间传递模型计算的 `P_post`：

```text
P = PStart(k)
for (Phi_i, dt_i) in interval(k), in chronological order:
    Q_i = 0.5 * (Phi_i @ Qc_pred @ Phi_i.T + Qc_pred) * dt_i
    P = Phi_i @ P @ Phi_i.T + Q_i

P_pred = P
S = H @ P_pred @ H.T + R
K = P_pred @ H.T @ inv(S)
delta_x = K @ Inno

position_post = GNSSMech_position - delta_x_position
P_post = (I-KH) @ P_pred @ (I-KH).T + K @ R @ K.T
```

`P_post` 可用于数值验证，但当前样本独立训练的下一样本仍应从数据文件中的 `PStart(k+1)` 开始。

## 6. Python 实现约定

### 6.1 时间键

- IMU/Vel 使用 `sample_window_key(t) = floor(t) + 1`，对应 `[k-1,k)`。
- Phi 使用独立的 `phi_window_key(t) = ceil(t-tol)`，对应 `(k-1,k]`；当前 `tol=1e-7 s`，用于吸收整秒时间戳的浮点写出误差。

### 6.2 可变长 Phi batch

- 数据集不再要求 `len(Phi_seq)==100`。
- 当前一秒模型只保留“上一成功 GNSS 时间恰为 `k-1`”的样本；GNSS 中断导致的多秒 PStart/Phi 区间会显式跳过。
- 每个数据集以其最大 Phi 步数补齐：补齐 `Phi=I`、`dt=0`，并返回布尔 `Phi_mask`。
- Kalman 传播只在 `Phi_mask=True` 的步上更新 P，补齐步不改变 P。
- `data065517` 的实际对齐样本中出现 102 和 106 个 Phi 步，证明 Phi 不能固定为 100。

### 6.3 协方差与位置更新

- `kalman_filter()` 接收 `Phi_seq/Phi_dt/Phi_mask`，按时间顺序使用 C++ 同款公式逐步构造 `Q_i` 和传播 P。
- 15 维正缩放因子通过 `D=diag(sqrt(scale))`构造 `Qc_pred=D Qc D`，保留原始 Qc 的对称性和非对角结构。
- ECEF 位置输出实施为 `GNSSMech_position - (K Inno)_position`。

## 7. 当前已确认与待验证边界

已确认的数据语义：

- `Phi` 时间戳是传播终点；
- `PStart(k)=P_(k-1)+`，键 `k` 标记目标 GNSS 更新；
- `GNSSMech(k)=x_k-`；
- ECEF 位置创新是 `INS-GNSS`，名义位置应减去 Kalman 估计的位置误差；
- Python 不需要重做惯导机械编排，但必须重做逐 Phi 的协方差传播。

右闭 Phi 归组、可变长 batch、逐 Phi/dt 传播和位置减法反馈已实现。剩余的关键验证是：用不缩放的原始 `Qc` 重放，与 C++ 同时刻输出的 `P_k- = m_GLSInfo.SINSPPre` 进行数值对照。

## 8. 数据验收要求

每条轨迹至少检查：

- 必需文件存在且矩阵形状正确；
- 样本键在 `PStart/H/R/Inno/GNSSMech/reference` 之间可对齐；
- Phi 序列严格按终点排序，`dt > 0`，区间无重复、无缺口；
- `PStart/Qc/R` 对称，对角线和特征值符合协方差/噪声矩阵的基本要求；
- 原始 `Qc` 的 Python 重放结果与 C++ `P_pred` 在指定容差内一致；
- 训练归一化统计仅由训练轨迹产生。
